Website Manager

Update the portfolio without touching code.

The Projects & Gallery manager is the source of truth for project photography. Publish once and the website rebuild automatically updates the main gallery, relevant service pages, featured work and search sitemap.

01 · New project

Create one entry per project or photo set.

Use a clear title, choose the category, add a short factual summary, and optionally add a city or service area. Never publish a customer's street address.

02 · Photos

Choose a cover, then add the rest.

The cover is the first image customers see. Add additional photos below it and drag them into the order you want. JPG, PNG and WebP uploads are automatically converted to optimized WebP and resized for the site. Add accurate image descriptions when practical; the site has safe fallbacks if one is left blank.

03 · Visibility

Control where it appears.

Published controls whether it appears at all. Featured places it in the home-page work section. Detail Page creates a dedicated project page for stronger portfolio depth and SEO.

04 · Publish

One publish triggers the site update.

Publishing commits the content and images to GitHub. Netlify then rebuilds and deploys the current site automatically. Normal updates do not require ZIP uploads.

iPhone / HEIC photosThe website manager standardizes JPG, PNG and WebP uploads automatically. HEIC is not a reliable web-display format; convert HEIC to JPG/WebP before uploading, or capture future iPhone photos in a web-compatible format.
Commercial work vs. bid-pack referencesOnly publish work actually completed by HQ Construction & Remodeling. Bid-package reference folders, inspiration images and unawarded commercial scopes should stay out of the public portfolio.

First-time connection only

  1. Use the existing Netlify project and deploy this final package once.
  2. In Netlify go to Project configuration → Build & deploy → Continuous deployment → Repository and choose Push to new repository.
  3. Create the repository exactly as Uniidens/HQ-Construction-Website, keep the production branch as main, and make this dedicated website repository public. The site source contains no credentials; Netlify secrets remain in environment variables. Do not use or overwrite the existing Uniidens/HQ-Construction repository; that is a separate application.
  4. In GitHub create an OAuth App with callback https://api.netlify.com/auth/done.
  5. In Netlify add that GitHub OAuth provider under the project's OAuth/Security settings.
  6. Return to https://hqconstructionllc.com/admin/ and sign in with the GitHub account that has write access to the repository.

The CMS uses Decap's direct GitHub backend through Netlify OAuth. Git Gateway is intentionally not used.
